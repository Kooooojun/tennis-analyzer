# knee-3d 結果（對照 knee-3d_pred.md）

## 做了什麼
- `pose_full.py` 另存 `pose_world.npy`（公尺、髖部為原點、frames×33×3）。
- `metrics.py`：`knee`＝2D（定義不變）、新增 `knee3d`、`knee_warn`（|3D−2D| > `KNEE_GAP_MAX`=20°）。沒有 world 資料時 `knee3d`／`knee_warn` 為 null。
- `export_session.py` 把 world（KEEP 17 點）放進 clip，`refine.py` 移動接觸格後能重算 3D。
- 網頁與精華：有 `knee3d` 就顯示 3D；旗標成立標「這拍角度不準」；手肘不顯示數字。

## 門檻理由
沒有真值，只能用分布與 angle.md 判斷：angle.md 的 2D 投影誤差 p95 約 15–25°，wall-1 的 gap 在 14.6° 之後跳到 21°，網路片最大 17.3°。取 20°：只抓 wall-1 的離群 2 拍（約 9%），網路片都不旗標。這是經驗值，雙機實驗（README）後要重新定。

## 預測 vs 實際
1. wall-1 IQR 3D < 2D：**成立**（15.5 vs 18.7，約 83%，落在預測的 60–90%）。只有 22 拍、沒逐拍校正接觸格，樣本小。
2. 網路片兩視角中位數差 3D < 2D：**勉強成立**（4.7 vs 5.4°），差距太小，不能說有顯著改善。預測的「2D 差 10°+」沒出現。斜前方片 3D 比 2D 低 10°（2D 偏直），與 angle.md 的偏差方向一致。
3. 旗標：wall-1 91% 不旗標（成立）；「網路斜前方旗標比例明顯高於 wall-1」**不成立**（0/6）。
4. 舊場次相容：`measure_full` 不給 world 時 `knee3d=None`，網頁用 2D；程式碼層面驗證，沒有實際跑舊場次的網頁。

## 限制
- 沒有真值，3D 比 2D「更準」未證明；只證明離散度略小。
- 手肘資料欄位還在，只是 UI 不顯示。
- wall-1 沒做 refine 逐拍校正、沒寫 notes.json。
