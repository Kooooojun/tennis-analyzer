# 側面整身左右對調：多機位參考量測

對應 #61。資料為 CalTennis（CC BY-NC-4.0），沿用既有研究的一個場次、兩位球員、四機各約五分鐘。影格、逐格骨架、標籤及截圖只留本機；本文件只放彙總。

## 參考的定義與限制

這是有拒判條件的多機位幾何參考，並非獨立動作捕捉或人工左右標註。兩機 2D 仍來自 MediaPipe；重投影誤差低不保證解剖左右正確，兩機共同反標也能幾何一致。因此先對兩種 partner 左右配對做 DLT，再用鼻相對肩中心、腳尖相對腳跟的水平面向，分別檢查肩線與髖線的解剖左右。

條件在正式量測結果揭露前寫入本機事前預測：支援關節最大重投影誤差 ≤20 px、中位數 ≤10 px；兩種配對的誤差中位數差 ≥1 px；兩種面向來源對肩、髖的正規化三重積絕對值均 ≥0.2、符號一致；鼻／腳尖水平向量至少 3／5 cm，肩髖寬 8–80 cm、軀幹長 15–100 cm，支援點均在兩機前方。肘、腕參考點也須通過 20 px 上限。

正式輸出與參考重投影分別配對肩、髖、膝、踝、肘、腕六組左右點：每組的正確或交換配對距離須有至少二倍優勢，六組方向全同才標正常或整身對調；混合方向另列，不拿軀幹標籤強翻正常手臂。髖中心偏移達參考軀幹長一半、缺點或無明確距離優勢時拒判。再把 partner 同步移動 −1、0、+1 格，三者都通過且判定相同才納入穩定真值。

- 同步：沿用既有雙機對時，±1 格擾動只是敏感度檢查，不能證明完全同步；快速動作的線性插值仍可能失真。
- 三角測量：錯人、退化深度與相互矛盾的左右配對可能通過部分幾何檢查；拒判條件只能降低風險。
- 背面：模糊臉與背對鏡頭會使鼻方向不可信；腳步外八、交叉步與軀幹扭轉也可能讓面向來源矛盾。不合格格不能當正常格，結果只適用於可判定子集。
- 模型共同偏差：參考不是完全獨立於被測模型；不能把保留機評估稱為跨球員、跨場地驗證。

## 正式流程與時間對齊

逐機以 `tools/pose_full.py`、heavy 模型、`METHOD="4"`、單人追蹤執行，提供全解析度來源讓既有遠景裁切路徑自行判定。每支分別取得 heavy 鎖，監測 free + inactive，不同時跑兩支。

原始影片近 60 fps 且其編碼長度與附帶時間戳不完全相同；以既有參考的開始解碼格及長度裁片，`setpts=N/(60*TB)` 逐格重設時間基底，沒有複製／刪除參考格。保留原時間戳供雙機對時。這可對齊本次沿用的解碼序號，不能反過來證明資料集所有時間戳都對應正確影格。

方位角採既有定義：0° 為鏡頭位於胸前、90° 側面、180° 背後；使用參考髖線及校正相機位置。區間左含右不含，180° 歸最後組。

## 可重現方式

`<參考目錄>` 含既有 `ct_pose.py` 以 300–600 秒產出的四機 npz；`<候選表>` 為既有 `ct_eval.py` 輸出。本次固定沿用候選，不用新標籤重新挑有利的拍。

```sh
.venv/bin/python tests/test_ct_lr.py
.venv/bin/python docs/research/caltennis/ct_lr_run.py 1 <參考目錄> work/i61-side
# 每支完成並釋鎖後，依序執行 2、3、4。
.venv/bin/python docs/research/caltennis/ct_lr.py <參考目錄> work/i61-side <候選表>
```

`reference_*.npz`、`truth.npz`、`strokes.json`、`summary.json` 及逐機執行紀錄全部寫在本機輸出目錄，不加入 Git。量測工具會拒絕覆蓋已有的姿態結果；輸入或研究規則改變時應使用新的本機輸出目錄，不能沿用舊參考快取。
